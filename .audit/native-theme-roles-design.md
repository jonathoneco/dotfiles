# Native-backed offline Herdr snapshots

Base candidate three; retain direct variant.herdr snapshots and adapter.herdr(variant, spec). Add one small native reader module for shared shipped-lualine lookup and mechanical RGB/highlight pair reading. Do not add universal UI schema, dataclasses or per-color provenance records. Provider expressions in adapters and pinned source are the provenance; independent literal native-role expectations and real rendering prove them.

Contract: each variant requires herdr with exactly20 supported fields: accent, accent_text, panel_bg, sidebar_bg, active_row_bg, selection_bg, surface0, surface1, surface_dim, overlay0, overlay1, text, subtext0, mauve, green, yellow, red, blue, teal, peach. Fields are lowercase #rrggbb; structural backgrounds may be reset. Each adapter implements herdr(variant, spec) after apply(). It reads its provider palette/highlights. Native shipped normal.a gives accent pair; providers without it explicitly use native StatusLine pair, preserving reverse attributes. No implicit ANSI4 accent or interpolated shades. Separator surface_dim is a native border/muted foreground, not a background.

Shared config/theme_native.lua functions: statusline(spec, variant) returns shipped module table or nil; hex(color) normalizes RGB; color(group, component, fallback) reads resolved highlights with explicit provider-color fallback; pair(group, foreground, background) resolves reverse and inherited components; accent(spec, variant, fallback_pair) uses shipped native normal.a or caller's explicit native pair. Existing runtime statusline_theme uses statusline() too; remove duplicate loader. Native editor behavior/transparency remains unchanged.

Preserve transparent Herdr panel_bg, sidebar_bg and surface0 as reset. Preserve Ghostty opacity and Neovim transparency. Native selected/active backgrounds, separator foreground, text/muted, and status roles replace generic/blended mappings. Repeat native roles for Herdr fields where provider has no separate counterpart; document standard role aliases once. Missing native status groups use explicit provider semantic/terminal colors, not Neovim core defaults mislabeled as native.

scripts/theme-native.lua checks/writes terminal and herdr together after plugin-pin check. bin/ghostty-theme validates all20 fields at catalog boundary, then serializes the stored fields for supported fixed/adaptive choices. Keep schema1 with new required field (all readers/fixtures migrate in same change; no legacy catalog mode). Unmanaged current choices retain terminal-only fallback and exact cancellation baseline. No new state file, process, per-preview Neovim, or app reload introduced.

fzf uses base16 in managed settings and picker argv so launch contexts without the options file still inherit native16 colors. Keep named/default overrides only. Real managed-config PTY test rejects fixed256 slots and unexpected RGB. Existing preview/cancel/adaptive tests remain authoritative for transaction behavior.

Implementation order: independent Melange literal-role regression red; shared readers and snapshot+consumer validation scaffold; family adapters in two isolated lanes; native role snapshots checked and integrated; fzf fix with real PTY gate; full installed-Herdr rendering and existing regression suites; review/docs/PR. No merge/deploy without new user instruction.

Tradeoffs: direct consumer field coupling avoids a second semantic vocabulary for one consumer. Herdr cannot use a separate native selection foreground, so retain its text-role behavior and verify readability. Preserve transparency rather than introduce opaque panel surfaces. Existing prompt/Bat/tmux limitations remain explicit.
